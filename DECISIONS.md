# Decisions

Every choice quackpit made where its brief left room, and why. quackpit was built in eight rounds before its first release, 0.1.0; a round names a stage of that work, not a release. The first round's choices come first, kept or revised in place, then what round 2 added (43 on), round 3 (60 on), round 4 (72 on), round 5 (96 on), round 6 (121 on), round 7 (156 on), round 7's late fixes (181, which went out with round 8) and round 8 (182 on). Where a choice departs from the brief's wording, it says so.

## How it is built

1. **Folder.** The plugin-authoring skill writes mods to a per-session dev-mods folder; the brief says to build in `~/projects/quackpit-mod`. The brief wins: the mod lives here and loads with `claude --plugin-dir ~/projects/quackpit-mod`.
2. **Engine version.** The brief names Claude Code 2.1.295; this machine runs 2.1.296, which wrote the type declarations quackpit is checked against. Everything was built and tested on 2.1.296. `$.ui.notify` (2.1.295+) is still called inside `try`/`catch` with a toast as fallback.
3. **`$` lives in one file.** The engine reads a hooks module statically and follows `$` only into functions declared in the same file (confirmed with `claude plugin validate`). So every `$` call and hook is in `hooks/register.tsx`. Building elements from the surface's table needs no `$`, so it lives in `hooks/draw.tsx`; the brief lists only `register.tsx`, and `draw.tsx` is adapter code all the same (it imports Claude Code's element types), which keeps `src/` free of any Claude Code import.
4. **Session state in `$.state`, typed as JSON.** The cockpit (everything observed this session) and the UI state are kept by the host, so a hot reload or a `/config` change (which reloads the module) keeps the band where it was. `claude plugin validate` refuses a state contract that imports anything, and `src/` must not import the Claude contract, so `types/index.d.ts` declares both values as plain JSON; the real shapes live in `src/model.ts` and every read is checked (`asCockpit`, `asUi`) before it is trusted.
5. **TypeScript is a dev tool, not a dependency.** `package.json` has scripts and no dependencies; `typecheck` runs a pinned `npx -p typescript@5.9.3`. No lockfile is created or committed. `.claude-plugin/types/` (this build's ~800 KiB declarations, laid by the engine on load) is git-ignored: it would break the 256 KiB per-file rule and is regenerated per release.
6. **Author** in `plugin.json`, `marketplace.json` and `LICENSE` is the repository's git `user.name`.

## What it measures

7. **Tokens are new tokens** (round 2; round 1 summed all four counts, token-detox's `sumUsage`): what a response read uncached, wrote to the prompt cache and generated. Cache reads stay out of every rate and total, because every request reads the whole context again: a 4-minute turn at a 490k context counted 4,976,971 tokens in round 1, 98.8% of them cache reads, and pace showed 0/h through the turn and then about 5M/h. Each main-loop response counts as it ends (`turn.step`, observed: chunks and the response pass on untouched, the time read alongside the request rather than before it, the fold done after the response is handed back), so pace moves during a turn; the turn's end (`turn.complete`, whose usage is its responses' sum) adds only what no step showed. The reads are shown instead as the cache's share of the prompts, read ÷ (read + write + uncached), in the pane: on the pace tile's second line it widened the tile and cut the hero's room, so the band leaves it out. A foreground subagent adds its Agent result's `totalTokens`, once, when the result arrives: that result's `usage` is its last response's alone (read in this build's code: `usage` is the last assistant message's, `totalTokens` its sum), and `totalTokens`, that response's whole prompt and answer, is what the run wrote and generated, each part of its context having been written once on the way (a probe: 23,613 against 23,768 new tokens summed over its two responses). A fork, whose prompt opens with the main thread's own transcript, adds its last response's new tokens alone. A subagent's own responses and turns carry its `agentId` and are never counted, so nothing counts twice; a background subagent's tokens are never seen by the main loop.
8. **Main agent and Claude's own calls only.** Every reducer ignores tool and turn events that carry an `agentId`, and a tool call another plugin raised (`next.origin.plugin` other than `engine`: a mod's own `$.tool.call` of Bash) is that plugin's, never Claude's check or command. The agents tile learns about subagents from the main agent's Agent calls and, for a background one, from `$.agent.list()` (every 5 seconds while one runs), so no subagent event is read at all. One launched as a cloud session (`remote_launched`) answers with a task id this session cannot list: it shows as launched, in the cloud, and keeps nothing running.
9. **Pace** is token-detox's `paceAt`/`pruneRecent` over the last 60 minutes, kept as one sample a minute (`addRecent`) so a busy hour of responses keeps every token. "Your usual pace" is the median of token-detox's `dayPace` over the last 14 days (3 days needed), else this session's own `dayPace` once it has 10 active minutes. The dial reads 0 to 2× usual: 1× straight up, amber from 1.5×, red from 1.8×. "Below 10 minutes of data" means quackpit has watched the session for under 10 minutes: the needle is grey and the tile shows the number and its label, nothing else.
10. **Forecasts** (round 2) read each plan window's own `percentUsed`, not tokens. The five-hour window's rate is a least-squares line through its readings of the last 90 minutes (3 readings, 10 minutes apart at least), so one jump of a whole point does not swing it; with fewer, it is the window's use so far over the time it has been open (its reset less 5 hours), once 10 minutes have passed. The seven-day window always takes its average so far: a 90-minute slope would read one working hour as the whole week. From the rate come the use projected at the reset, drawn after the used part of each meter in a second shade: the same `▰` dimmed (`5h ▰▰▰▰▱ 30% → ~75%`, the last two dim). The brief's example used `▓`, which most terminal fonts draw full-height and much heavier than the slim `▰` beside it, as the captures showed; and the time the window runs out when that comes first (`→ full ~16:43`, and the pace tile's `empties 16:43`); otherwise it "holds". A projection within a point of the reading is left out. An ETA before the reset turns the pace tile amber even below 1.5×. A reading whose reset time has passed is about a window that is over: it reads `reset`, with no countdown (never `↻0m`) and no caution, until the next reading.
11. **Thresholds.** Context: amber 70%, red 90% (the duck's), of the auto-compact point while auto-compact is on, else of the window (decision 45). Five-hour: amber 80% (the duck's), red 90% (the notification's). Seven-day: amber 75%, red 90%. Colour appears only there, and green only for a passed check or a finished list. The five-hour caution and its notification keep quiet when the window resets in under 30 minutes and its forecast says it lasts until then: nothing is left to do about it.
12. **Checks.** Detection reuses token-detox's `VERIFY_RE` as the first pass, widened by runners it does not list (`claude plugin test`, `node --test`, `cargo clippy`, `biome`, ...), then confirms the kind on each shell segment after stripping wrappers (`npx`, `pnpm exec`, `pnpm vitest`, env assignments), so `cat jest.config.js` is no check. `pnpm check` counts as a test run. A check fails on a non-zero exit, or, where a pipe, `;` or `||` may hide the exit, when its summary line names failures; where nothing can hide it, a clean exit passes whatever the output mentions (a summary count must also end its clause, so "2 failed attempts" is none). A command that never ran is no check at all: Claude Code answers the permission dialog's no, a rule, a hook and the Bash tool's own refusal (it blocks a leading `sleep`) with an error, as it does a failure, so its words decide. A command that ran and failed reads `Exit code N` (Claude Code's own shell error); Esc leaves `[Request interrupted by user…]`, which reads as interrupted, not failed; a shell error with neither, and no runner's summary in what it printed, never ran. Counts come from the summary lines of vitest, jest, pytest, cargo, mocha, `node --test`, tsc and eslint. The time shown is measured around the tool call. A typecheck or lint that passes without printing counts reads "clean".
13. **Cost** is Claude Code's own ledger (`/cost`): the session's total, and a turn's growth from its start to the first reading after its last response (the one `session.measure` pushes after the turn, or the next turn's start; a reading already taken after the last response settles it at the turn's end). A turn judged in USD waits for that reading to be judged. A turn over 3× the session's median is judged in USD once 5 earlier turns were priced, else in tokens, as token-detox does. Interrupted turns and turns with no usage stay out of the medians: they are no sample of a normal turn, and a few of them would halve the median.
14. **Progress** follows `TodoWrite` (which replaces the list) and `TaskCreate`/`TaskUpdate`/`TaskList` (which maintain one); this build's sessions offer the Task tools, so both are needed. The current item is the one in progress, else the next pending. A finished list stays until a later turn starts. Big digits are for the list's `done/total` alone (round 2): round 1 showed the turn's elapsed time there, which repeated Claude Code's own spinner clock just above it, ran a second or two off it and read like a time of day. With no list the hero shows what the turn is doing (from the tool in flight) and `turn N · M tools`, and between turns the last turn at minute resolution.
15. **The goal** is the first prompt the person sent (typed, from the phone or the SDK), never a slash command or another plugin's prompt. Rebuilt from a transcript it is the first row the person typed: never Claude Code's compaction summary ("This session is being continued from a previous conversation…"), a command or its output, a reminder, hook or task output, the caveat before local commands or an interruption's marker. When the summary comes before any typed row, the first prompt is gone, and the mission says so ("Unknown: …") rather than take a later prompt for it.
16. **The session tile** takes the model from `$.session.model()`, effort and permission mode from the `Stop` settings hook's input (the one event that carries both), and its time from when quackpit started watching.

## Layout and look

17. **`rows` counts terminal rows.** A tile is 2 rows tall (a gauge beside two lines of text), so the hero's number can be big and the gauges can have a shape. `rows 2` is one line of tiles, `3` adds a dense row of the tiles that did not fit, `4` wraps the tiles onto two lines, `1` is the dense row.
18. **Graceful narrowing.** When tiles do not fit, the rightmost first switch to compact faces (a `◔◑◕●` ring, a one-row tachometer, limits without meters); what still does not fit becomes `+n`, which opens the pane. Under 80 columns the band is one dense row whose hero title takes the room the other readings leave.
19. **Block characters, not braille.** Braille gauges were tried first and render faint in the fallback fonts macOS terminals use. The text mode uses half and eighth blocks, which every terminal draws solid: a 3x4-pixel block font for the hero's number, a tachometer of rising bars for pace, a half-block ring for context, `▰▱` meters for limits, `▁▂▃▅▇` for the cost sparkline. Text uses the theme's own colour keys (`success`, `warning`, `error`, `subtle`, `inactive`), so light and dark themes both read.
20. **Pixels where the terminal shows them.** With `graphics: auto`, the band draws a 1x1 probe `Image` once and blits it: the engine takes the blit where the terminal shows pictures (kitty graphics: kitty, Ghostty) and refuses it where the Image draws its alt. Taken, the dial, ring and duck become anti-aliased RGBA images drawn in pure TypeScript; refused, they stay text. Images cannot follow the theme, so they use mid-tones that read on dark and light.
21. **The desktop variant** draws the same gauges as SVG (the desktop's table has `Svg`, not `Raster` or `Image`): a needle dial, a ring, the block digits, a sparkline and the duck. Neutral ink follows `prefers-color-scheme` inside the SVG.
22. **Gutters** are one cell holding a dim `│`, the thin rule between tiles. Each tile's first line is a plain `Button` that opens the pane; pictures cannot be buttons.
23. **The pane** (round 2) opens on a six-pack of the tiles: the band's in its order (by default exactly the six instruments), then every other tile that measures something (the placeholders only when they are in the band). Each cell has a dim title, its 2-row gauge or the hero's digits beside two lines, and at most one line of detail; thin rules (`│`, `─┼─`) part the cells, with no boxes. From 90 body columns the grid is 3 across, from 60 it is 2, below that one. Under it come the cautions and the mission, a line each, then the time section (decision 48), the last 20 turns, the layout's add and remove buttons and the handover preview as Markdown. `/quackpit` toggles it; it never opens unasked. (round 4: pace and limits became the pace row's dials and the grid reads in pairs, decisions 82 and 87; the mission and cautions wrap to two lines, decision 89. Round 5: progress opens the pane, each cell opens its detail, and what follows the mission is tabbed, decisions 96 to 107.)
24. **The spinner.** While a task list runs, the spinner's ellipsis carries its count (`Writing tests… 3/7`). Drawing only.
25. **Sharing the band** (round 2; round 1 hid any band beneath its own). The engine shows the tree of the hook it asks first, so quackpit asks for the band beneath it once, before anything else (`next(e)`: a second call would run every hook beneath again), and draws its own rows under it, nearest the prompt. Where no hook beneath drew, `next(e)` answers the engine's own element (`{ type: 'engine' }`, an empty band there; this build's types and a live session agree), and quackpit leaves it out. It hands the band beneath on alone when a survey holds the band, on a surface it does not draw, when it has nothing to draw, and when its own drawing throws. Beside another band, which it cannot measure, quackpit takes the rows the person allows only while at least 4 stay for the band beneath (so its 2-row grid from `maxRows` 6, 3 rows from 7, 4 from 8), else its one dense row, and nothing when `maxRows` is under 2. A mod above quackpit that does not hand the band on (token-detox 0.1.0 is one) still hides it: both bands show only when every mod asked before the last one forwards.

## The duck

26. **An original rubber duck**, drawn here at 16x16 (pixel and SVG variants), 12x4 (the terminal's 2-row cell) and 8x2 (the one-row band). Round 2 redrew it three times. First the terminal's duck: round 1's 8x4 in half blocks gave the head 2x2 pixels and a 1-pixel eye against the beak in a near-background colour, which read as a hole, so it became 16x4 in quadrant blocks (the brief's candidate B). The person then found that duck too long: a quadrant pixel is twice as tall as it is wide, so 16x4 of them drew a duck about twice as wide as tall, its body a long bar. A 10x4 redraw with a big head, a pink cheek and a glinting 16x16 eye was, in the person's words, too fat and too sparkly. The duck kept is between them: 12x4 in 6 columns (about 1.5 wide to 1 tall), a round head over a body that narrows underneath, an upturned tail, a two-pixel bill and a plain dark eye with no glint and no cheek; it leaves the tiles two more columns than round 1's. Each cell holds 2x2 pixels in at most two colours (clear counting as one, and clear is the terminal's own background), its glyph the quadrant block of its pixels' 4-bit mask, the fewer-pixelled colour drawn over the other. The palette is body #ffd23f, wing shade #f2b72a, belly #e0a91c, bill #ff8a1f, open mouth #7a2a10 and eye #2b1d18 (a warm dark, not near-black). Three frames, the body the same in each: `idle`, asleep with its eye shut, drawn as a `-` of eye colour over yellow where no quadrant can draw a line; `alert`, eye open, bill open to the head's full height; `shut`, the same with the bill closed. The one-row band's duck stays 8x2 (`Y...YY..` over `YYYYYYOO`). The 16x16 duck, for terminals that show pictures and for the SVG surfaces, has the same shape: head 6 pixels wide, body 14, eye a 1x2 dark mark, the shut eye a 2-pixel line, the open bill orange over a dark mouth; its picture is centred in the 2-row cell's own shape (6 columns by 2 rows), so a terminal that fills the cell does not stretch it. Every candidate was compared as the terminal draws it, at true size and enlarged, on dark and light backgrounds.
27. **It moves once per caution.** A new caution draws it idle, then four blitted frames (head up, bill open, shut, open, shut, about half a second) and it holds `shut`, eye open and bill closed, the pose a standing caution keeps. Nothing runs while it is idle. The quack is due when a caution is announced and plays at the band's next draw; neither a redraw nor a reload plays it again.
28. **Cautions have keys**, so a new cause raises it again: a failed check per run, the five-hour window per reset, the context per compaction, a runaway per turn. Each key gets one announcement. Clicking "Quack:" acknowledges, like pressing the Master Caution light: the duck settles, the gauge stays lit until the cause clears. The cell names the worst open caution, then by kind (a failed check, the 5h window, the context, a runaway), then the newest: ordered by time alone, the gauges' cautions, which carry the latest reading's time, would trade places at every reading.
29. **Notifications** go only to a failed check and the five-hour window at 90%, as an OS notification instead of the toast, at most 3 a day across sessions (a counter in the store; a slot is given back when a notification does not go out). Within a session the slots are taken one at a time; the store has no atomic update, so two sessions notifying in the same instant could each take the last one. They are never awaited by a turn: the person's own Notification hooks run first. `/quackpit duck off` silences the toasts, notifications and sound too; the gauges still turn amber and red.
30. **The quack sound** is a WAV synthesised in code (a falling nasal buzz through two formant filters), because the repository may hold only text, SVG and PNG files. Off by default, at most once every 20 seconds.

## Handover, commands, storage

31. **The handover** is written to `<project root>/.claude/handover.md`, copied with `$.ui.copy` (which this build offers), and shown in the pane. It opens by saying to treat every line as a starting point, not a fact (decision 50 lists its sections). Credentials are masked as quackpit takes them in: the goal, each turn's prompt, task titles, commands and output (env assignments and flags, `-u user:pass`, API-key and Authorization headers, `mysql -p…`, quoted JSON and YAML secrets, URL credentials, and the shapes of Anthropic, OpenAI, GitHub, Slack, AWS, Google, Stripe, npm and GitLab tokens and JWTs). Next shift gives the failing output of each kind of check whose latest run failed: a lint that passed later does not hide a test still failing. The demo's handover is shown, never written into a project. "Shift change soon" shows once a session, from the reading or response that carries the context past the smaller of 200k tokens and 80% of the auto-compact point (of the window while auto-compact is off), until the next turn ends or the handover is written: on a 1M window 80% is 800k, far past where quality slips (about 200 to 300k).
32. **Commands answer with an empty result** (and are `immediate`, so they work mid-turn): a command's text would be a transcript row the model reads. Everything a command says goes to a toast or the pane.
33. **Layout overrides** from `/quackpit add|remove|move|rows|duck` live in the store and apply to every session until the userConfig values they were made against change; then the setting wins (token-detox's rule). `/quackpit reset` drops the override.
34. **claude-hud** is read once, on the first session, from `$CLAUDE_CONFIG_DIR` or `$HOME/.claude` (the two paths in the brief), the per-directory file layered over the shared one as claude-hud does. Mapping: todos → progress, usage → pace and limits, tools → checks and files, agents → agents, git or duration → session, cost → cost; context is always on in claude-hud and maps to context. The hero is always first.
35. **Resumed sessions** come back from their record when quackpit kept one (decision 46); otherwise they are rebuilt from `$.session.messages()`: goal, task list, files, commands and checks. Their old cautions are marked seen and acknowledged, so the duck never quacks about history. Pace, turn costs and the history start from the resume. The transcript carries no times, so what it gave back says "earlier" (이전) in the band, the pane and the handover rather than the moment quackpit read it: the same path runs after `/reload-plugins`, an install mid-session and a `/config` reload, where "before the resume" was wrong. A session quackpit joined under way says "Watching since HH:MM" until its first turn, not "No turns yet".
36. **`/clear`** (`session.end` with `clear`) starts a fresh cockpit, which takes the new session's id at the next turn and counts its turns from 1 (the new transcript's rows would count `/clear` and the prompt now starting); any other change of session id is noticed at the next turn and rebuilt from the transcript.
37. **Redraws** (round 2). Nothing in the band shows seconds that tick any more: running checks and agents, the session's time and every "ago" read in whole minutes (`<1m`, `4m`, `just now`, `4 min ago`). So the band redraws when an event changes the cockpit (a state write redraws its readers by itself) and on a timer every 30 seconds for the countdowns and ages; the timer ticks each second only while the demo plays its script. While a background agent runs, `$.agent.list()` is looked up every 5 seconds by a timer of its own, which redraws only when something changed. The timers work from what the last write left in memory, not from reading the state.
38. **Start-up.** `session.start` holds the first prompt, so quackpit builds the cockpit there (the layout, a resumed transcript, the first reading), waiting at most 1.5 seconds: past that the session goes on and the cockpit fills in after. A turn's start is folded in before the turn goes on, so its tool calls land in it; everything else a hook does is a few local reads and writes.
39. **Storage.** The store keeps the layout override, a once-only claude-hud flag, the day's notification count, the session records of decision 46, and one `np:<day>:<session>` record per session-day (new tokens and active minutes) for your usual pace. Finished days roll up into `nd:<day>` at the next session start; days older than 30 are dropped. Round 1 kept the same records under `p:` and `d:` in all four counts; the roll-up deletes them, so your usual pace starts over in the new unit (this session's own average stands in until 3 days are in) rather than mix two units. Usually a few dozen KiB in all; with twenty session records at their very largest, under half a MiB, still far under 2 MiB.
40. **The demo** is a 62-second script driven by the clock (each frame is a function of the time since it started), localised in Korean, marked `demo` in the band, and it ends itself five minutes after its last frame. Round 2 re-scripted it to show what is new: it opens at 2 of 6 tasks with `~26m left` (tasks have lengths, laid back from each frame's now, so the estimate shrinks as they finish), a test run fails and the redrawn duck quacks, the five-hour forecast runs out (`→ full ~HH:MM`) and recovers, the context passes the shift-change point (140k) and comes within 11k of the auto-compact point (the duck again), a compaction brings it down, and the list completes; the pane shows the six-pack, the time section with three subagents (one in the background) and the cache clock.
41. **The health seam.** `src/health.ts` exports `registerHealthSource`; the `health` and `streak` tiles read the newest source and say they arrive in the next round while there is none. (round 4: they are hidden until a source registers, decision 92. Round 5: the seam is gone, health is quackpit's own and streak leaves the code, decisions 108 to 112.)

## Tests

42. The tests run under `claude plugin test .`. A test that drives a session may take 20 seconds (`LIMIT_MS`): each takes well under a second on a quiet machine, but on one busy with other work the kit's own 5 seconds ran out. The kit cannot raise a subagent's `tool.call` (`$.tool.call` drops `agentId`), so subagent exclusion is tested on the pure reducers. The kit's answers for a refused, blocked or interrupted shell call use Claude Code's own words, copied from this build.

## Round 2

43. **Readings are pushed.** `session.measure` brings the context, plan windows and ledger after each main turn and whenever a plan window moves a point; quackpit reads `$.session.usage()` itself only at start-up and at a turn's start, as a fallback, and no longer on tool calls. Between readings the context's fill comes from the main loop's latest response, whose prompt (uncached, cache-read and cache-written together) is the figure the status line shows; whichever of the two is newer wins. After a compaction the fill is unknown until the next response says it, as the engine has it. A reading that carries no plan windows (a direct read as the session opens can come before Claude Code has them) keeps the last reading's windows until their reset, and the ledger; the context's fill is never carried. And the session's first measurement, which can arrive while quackpit is still starting, is kept through start-up rather than replaced by the fresh cockpit.
44. **Time left on a task list.** Each task keeps when a call first showed it in progress and first showed it completed, from the TodoWrite, TaskCreate, TaskUpdate and TaskList calls' own times (a TodoWrite rewrite finds each item's earlier self by its words; a task that reopens loses its completion). The estimate is the median length of the list's completed tasks times the tasks still open, less what the running task has had so far, in whole minutes after a `~` (`~9m left`, `~1h20m left`). It shows only once 2 completed tasks have a known length, and not at all where it would be nonsense: nothing open, the running task already past it, or over 12 hours. A task marked done without ever being seen in progress has no length and does not count.
45. **The auto-compact point.** `$.session.usage({ breakdown: 'summary' })` estimates the context's breakdown locally and sends no request; its `autoCompactThreshold` (absent when auto-compact is off) is read once at start-up and at most once a turn after that, when the turn's reading arrives. The context tile keeps its ring for the window and says how far the point is (`84k to compact`; the pane says `84k to auto-compact (it compacts at 967k)`). The ring's colour and the duck's context caution measure the context against the point while auto-compact is on: the caution comes within 10% of it (`87k to compact`), so on a 1M window compacting at 967k it comes at 870k rather than at 900k of a window the session never reaches, and on a 200k window compacting at 167k at about 150k rather than never. With auto-compact off, the caution stays at 90% of the window.
46. **The session's record.** `$.state` lasts as long as the process, so a restart (a resume, an update) used to rebuild only what the transcript still holds, with no times. Now each session keeps a record under `s:<session id>` in the store: the cockpit cut down to what the pane, the handover and the forecasts show (the 20-turn history, the task list with its times, the last 8 checks and the latest failure of each kind, subagent runs, the edits and commands kept, pace and five-hour samples, working time, and when quackpit started watching), without what is only true now (the turn running, the last reading and response). It is written at most once a turn, after the turn ends, and read back when a process finds no cockpit for its session, before the transcript, which is then not replayed over it: the record holds the same calls with their real times. The turn that was running when the process stopped is lost. Records are pruned at start-up to the 20 written last, none older than 7 days. A record at its very largest is under 24 KiB (texts cut to 80 characters, paths to their last 80, failing outputs to their last 300, the later prompts to 100 and the last one to 600), so twenty stay under a quarter of the store's 2 MiB; an ordinary one is a few KiB.
47. **Unverified edits.** Each main tool call gets its place in the session's order as it starts, and each edit is logged with it, so "after the latest passing check" holds without times (a rebuilt transcript has none) and for an edit made while a check ran (that check did not see it). After a pass, the checks tile's second line gives the edits no passing check has seen since (`tests · 2 edits since`) in place of its age; a pass of any kind counts, since any check that passed looked at the code as it then stood. The pane draws the check history as one square a run, newest on the right: green for a pass, red for a failure, a hollow square for a run that was stopped; nothing else in it is coloured.
48. **TIME, TASKS, SUBAGENTS.** Under the grid, in the pane alone, in plain words. TIME: elapsed since the session began (`$.session.usage().startedAt`, its first launch for a resumed session), working time (the turns' durations summed, the running one's so far), the turns and the ledger's cost. TASKS: each task's mark (✓ done and dim, ▸ running, · pending), its title (masked as it came in) and length (`4m12` once done, `6m…` in whole minutes while it runs, since the pane redraws every 30 seconds like the band), and a bar on one time axis shared with the subagents, in eighth blocks like the pace dial, so overlaps show; the running task's expected end (its start plus the list's median task) is drawn ahead of it in a light shade, with the list's `~N min left` (decision 44) after the axis. Six rows show, centred on the running task, the rest folded into `+N more`.
